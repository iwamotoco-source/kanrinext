# 現場ネクストの保護範囲（2026-10-07）

普段の操作を増やさず、保存・送信時の漏洩経路を減らす変更。

## 端末保存

security-store.js が起動時に端末専用の AES-256-GCM 鍵を IndexedDB に生成する。
鍵は non-extractable。追加パスワード入力はない。予定・タスク・端末設定（GitHubトークン、AI/TTSアクセスキー含む）・同期比較用コピー・交通費・検査記録・電気技術の個人メモを localStorage に暗号化して保存する。
旧データは暗号化→復号一致確認して移行。読み取り・鍵取得に失敗したときは空データで起動・上書きしない。書き込み失敗は画面下に表示し、未保存処理中の離脱を警告する。
会話履歴のIndexedDBも本文を暗号化。画像/PDF/Excelの原本は従来どおり履歴に保存しない。複数タブで使うときの記録更新は従来どおり最終書込みとなる（共同編集用ではない）。

これは平文コピー・ストレージ内容の単純な閲覧に対する保護。鍵も同じ端末にあるため、端末丸ごとの窃取・ブラウザプロファイルへのアクセス・同一オリジンの悪意あるJavaScriptを防げない。OSの画面ロックと端末暗号化は必要。IndexedDBを消すと鍵が失われるので、暗号化バックアップを別途保存する。
書類作成ツールに登録するExcelひな形等、ここに列挙していない保存領域・明示的なCSV/ICS/JSON書き出しは対象外。

## GitHub同期・バックアップ

GitHubへの書込みは常にAES-256-GCM。平文の無効化設定・旧ghPut経路を閉じた。
新規暗号化はPBKDF2-SHA-256 600,000回。既存250,000回のファイルを同じパスワードで読める。復号時に方式、salt/IV長、反復回数・暗号文サイズを検証し、異常な処理量を拒否する。
同期パスワードは従来同様sessionStorageだけ（ウィンドウを閉じた後の再入力は従来どおり）。GitHubトークン・AI設定は同期しない。
主画面のバックアップは同期パスワードで暗号化して出力。復元は暗号化形式と旧平文形式の両方に対応。パスワードを忘れると暗号化バックアップを復元できない。

## ブラウザ・外部通信

主画面CSPでスクリプトを同一オリジンに制限し、inline script/event・object・外部iframeを禁止。wasmを許可しPiper-plusを維持。ツール内の旧inlineスクリプトは別ドキュメントで引き続き動作するので、CSPは全ツールを覆うものではない。
PDF編集・数量拾い・Excel画像抽出は同梱ライブラリだけを読み、CDNから実行コードを追加取得しない。
referrerは送信しない。復元ブックマークはhttp(s)だけ、iframeからの画面移動は同一オリジンかつ実際のツールiframeからのみ。
AIキー送信先はHTTPS（開発用loopback HTTPを除く）。AI/TTS/GitHubのキー付き通信・音声サーバーの上流取得はリダイレクトに追従しない。TTSのLAN内HTTP利用は既存互換を残す。
AIの予定送信、添付確認、ローカルのみ、操作候補の承認とUndoは既存の選択を維持。

## サーバー・公開

AI/TTSの診断GETにも認証を要求する。CORSは指定originの完全一致、productionでは自動localhost許可・ワイルドカードを廃止。POSTの実際の本文サイズも検証。追加の短時間制限はプロセス内だけで、分散レート制限/永続クォータの代わりにはならない。
Pagesワークフローは静的アプリのファイルだけを公開し、同期ファイル・サーバーソース等を成果物から除外。リポジトリ自体が公開であること、Gitの過去履歴が読めることは変わらない。併存していたブランチ直接公開にもJekyll除外設定を適用し、同梱vendorを明示的に含める。Vercelの静的配信も同期ファイルを除外する。
公開ソースの住所初期値を空欄にした。既存端末の住所設定は保持する。過去の履歴にある住所や過去の平文データはこの変更では削除されない。履歴の書き換えや鍵の失効は別作業で、既存同期への影響がある。

GitHub Pagesの他のプロジェクトも同じ *.github.io origin を共有する。キー名の分離はセキュリティ境界にはならない。より強い隔離には専用ドメイン/オリジンとサーバー側セッションが必要。
